# v1.2.0 — editable content and reliable motion

Candidate prepared on 8 November 2026. This document does not mean the candidate has been promoted to production or tagged.

## Changes

- Edit public résumé information through `content/portfolio.json`, with editor completion and validation before development/builds.
- Derive identity, contact links, metadata, social cards and numbering from that content. Multiple degrees and projects without custom diagrams are supported.
- Control animation with persistent Auto/On/Off preferences. Auto respects reduced-motion and data-saving preferences; CPU count alone no longer disables motion.
- Show a real portfolio-health observation when no external monitor is configured. External service state remains a separate optional integration.
- Reduce duplicate diagram markup and limit the content passed to interactive components.
- Refresh delivery copy, maintenance retry facts and framework/build dependencies.
- Add production-browser and accessibility checks to repository quality validation.

## Acceptance

Local acceptance is recorded in [FINAL_REVIEW.md](../FINAL_REVIEW.md). Before promotion, the exact pushed commit must pass GitHub quality checks, deploy to the Cloudflare preview and pass its hosted HTTP/browser checks. Production retains its required reviewer and main-branch restriction.

The optional homelab monitor is not connected. Eight moderate development-tool advisory findings, physical cross-engine testing and the existing live analytics/CSP mismatch remain documented. Production dependency auditing reports no known vulnerabilities for the reviewed lockfile.

## Recovery

The v1.1.0 tag is preserved. Keep production on its current known-good Worker until the candidate is accepted. If a later promotion needs recovery, roll back to the recorded known-good Worker version rather than moving an existing Git tag or reconnecting the old home-server origin.
